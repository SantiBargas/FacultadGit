PUNTO 1 — DHCP EN ROUTER0 PARA PC0, PC1 Y PC2
================================================================

El enunciado pide que Router0 otorgue IP a las PCs de acuerdo
a la IP de su Fa0/0 (10.0.0.17/29). La red es 10.0.0.16/29,
con gateway 10.0.0.17 y rango de hosts del .18 al .22.

Configuré el servicio DHCP directamente en Router0 porque las
PCs están en la misma subred que su interfaz Fa0/0. Cuando una
PC arranca y no tiene IP, manda un broadcast DHCP Discover —
como el router está en la misma red, lo escucha y responde
con una IP del pool que configuré.

Usé excluded-address para reservar la IP del propio router
(.17) y que no se la asigne a ninguna PC por error.

Comandos aplicados en Router0:

  enable
  configure terminal
  ip dhcp excluded-address 10.0.0.17
  ip dhcp pool SUBRED1
  network 10.0.0.16 255.255.255.248
  default-router 10.0.0.17
  dns-server 172.18.0.2
  exit
  exit
  write memory

Después fui a PC0, PC1 y PC2 → Desktop → IP Configuration
y tildé DHCP en cada una.

Resultado: las 3 PCs recibieron IP automáticamente.
  PC0: 10.0.0.18 | GW: 10.0.0.17 | DNS: 172.18.0.2
  PC1: 10.0.0.19 | GW: 10.0.0.17 | DNS: 172.18.0.2
  PC2: 10.0.0.20 | GW: 10.0.0.17 | DNS: 172.18.0.2

PUNTO 2 — SERVER_DHCP PARA PC3, PC4 Y PC5
================================================================

El enunciado pide que Server_DHCP (10.0.0.13) otorgue IP a
las PCs de acuerdo a la IP de la Fa1/0 del Router2 (10.0.0.25).
La red es 10.0.0.24/29, gateway 10.0.0.25, rango .26 al .30.

El problema acá es que Server_DHCP está en una subred distinta
(10.0.0.8/29) y las PCs están en 10.0.0.24/29. El broadcast
DHCP Discover que mandan las PCs no puede cruzar routers solo
— se muere en el primer salto.

La solución es ip helper-address en la interfaz Fa1/0 de
Router2 (la que mira hacia las PCs). Este comando convierte
el broadcast de la PC en un unicast y lo reenvía directamente
a la IP del Server_DHCP (10.0.0.13). El server responde, el
router retransmite la respuesta a la PC, y la PC obtiene su IP.

Lo puse en Fa1/0 (INSIDE, la que mira a las PCs) y no en
Fa0/0 (la que mira al backbone), porque el helper-address
tiene que estar en la interfaz por donde llega el pedido.

Configuré el pool en Server_DHCP → Services → DHCP:
  Service: ON
  Pool Name:    SUBRED2
  Default GW:   10.0.0.25
  DNS Server:   172.18.0.2
  Start IP:     10.0.0.26
  Subnet Mask:  255.255.255.248
  Max Users:    5
  → Click ADD

Comandos aplicados en Router2:

  enable
  configure terminal
  interface FastEthernet1/0
  ip helper-address 10.0.0.13
  exit
  exit
  write memory

Después fui a PC3, PC4 y PC5 → Desktop → IP Configuration
y tildé DHCP en cada una.

Resultado:
  PC3: 10.0.0.26 | GW: 10.0.0.25 | DHCP Server: 10.0.0.13
  PC4: 10.0.0.27 | GW: 10.0.0.25 | DHCP Server: 10.0.0.13
  PC5: 10.0.0.28 | GW: 10.0.0.25 | DHCP Server: 10.0.0.13

PUNTO 3 — NAT/PAT EN SUBRED 1 Y SUBRED 2
================================================================

Las PCs tienen IPs privadas (10.0.0.x) que no son enrutables
en el backbone público. NAT/PAT permite que salgan compartiendo
la IP pública de la interfaz WAN del router.

Usé PAT (overload) porque tengo varias PCs privadas que tienen
que salir por una sola IP pública. PAT las distingue usando
números de puerto distintos para cada sesión.

Para configurarlo necesité tres cosas en cada router:
1. Marcar qué interfaz es INSIDE (mira a las PCs privadas)
   y cuál es OUTSIDE (mira al backbone)
2. Una ACL que diga qué red tiene permiso de salir traducida
3. El comando que une la ACL con la interfaz pública y activa
   el overload (PAT)

La wildcard de la ACL es el complemento de la máscara /29:
255.255.255.248 → 255 - 248 = 7 → wildcard 0.0.0.7

--- Router0 (Subred 1) ---
INSIDE: Fa0/0 (mira a PC0/1/2)
OUTSIDE: Fa1/0 (192.168.0.1, mira al backbone)

  enable
  configure terminal
  interface FastEthernet0/0
  ip nat inside
  exit
  interface FastEthernet1/0
  ip nat outside
  exit
  access-list 1 permit 10.0.0.16 0.0.0.7
  ip nat inside source list 1 interface FastEthernet1/0 overload
  exit
  write memory

--- Router2 (Subred 2) ---
INSIDE: Fa1/0 (mira a PC3/4/5)
OUTSIDE: Fa0/0 (172.16.0.6, mira al backbone)

  enable
  configure terminal
  interface FastEthernet1/0
  ip nat inside
  exit
  interface FastEthernet0/0
  ip nat outside
  exit
  access-list 1 permit 10.0.0.24 0.0.0.7
  ip nat inside source list 1 interface FastEthernet0/0 overload
  exit
  write memory

Verificación: ping desde PC0 y PC3 a 172.18.0.2 → 4/4 en
ambos casos. El tráfico salió de las subredes privadas,
fue traducido por NAT y llegó al backbone correctamente.

PUNTO 4 — DNS Y NAVEGACIÓN WWW.CISCO.COM
================================================================

Para que las PCs puedan navegar a www.cisco.com necesitaba
que el Server_DNS resuelva ese nombre a la IP del Server_WEB
(10.0.0.10). Sin un registro DNS, el browser no sabe a qué
IP conectarse cuando escribe www.cisco.com.

También agregué los registros para FTP y EMAIL de una vez,
porque los puntos 5 los iban a necesitar también.

Configuré en Server_DNS → Services → DNS:
  DNS Service: ON
  www.cisco.com  → A Record → 10.0.0.10 (Server_WEB)
  ftp.cisco.com  → A Record → 10.0.0.11 (Server_FTP)
  pop3.cisco.com → A Record → 10.0.0.12 (Server_EMAIL)
  smtp.cisco.com → A Record → 10.0.0.12 (Server_EMAIL)

pop3 y smtp apuntan al mismo server (10.0.0.12) porque son
dos protocolos del mismo servidor de correo — POP3 para
recibir y SMTP para enviar.

Verificación: abrí Web Browser en las 6 PCs con
http://www.cisco.com → todas cargaron la página correctamente.
